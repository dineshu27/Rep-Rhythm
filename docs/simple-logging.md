# Simple logging and Basic helper

The main food workflow is now search or recent food → enter weighed grams → Add. Selected catalogue records are saved with the log in one update. The diary supports inline portion/meal edits, removal with undo, and repeating a meal from yesterday using its original nutrient snapshots. Saved-food/package editing is secondary. Search and Basic catalogue matching need a connection; recent and saved foods remain usable with browser storage offline.

Workout logging supports selecting exercises without first building a routine, logging an already completed exercise in one form, adding exercises during a live workout, and showing the last actual set values for the same exercise name and tracking unit. Prefilled values are suggestions for entry, never marked completed automatically. Quick completed logs explicitly do not estimate duration. Routine editing, weekly splits and coverage remain available in an expandable section. Existing plans, active sessions, records, backups and storage keys are preserved.

Basic helper is available without an API key. It is deterministic parsing and catalogue search, **not an LLM or a web search engine**. It handles explicit gram/kilogram portions, editable catalogue starters, simple meal ideas and summaries of recorded weekly facts. It cannot understand arbitrary conversation, infer weights from cups/counts, verify allergens, or personalise a medical exercise prescription. The UI labels it Basic helper. No OpenAI/Anthropic call is made on this path. Planning & coaching drafts require review and an explicit save. The primary daily chat now automatically saves clear completed reports, with review for missing or ambiguous details; see [daily companion](daily-companion.md).

When a personal OpenAI or Anthropic key is connected, the chat selects the available provider by default, while letting users choose Basic explicitly. Provider calls retain sharing consent, usage-charge consent, encrypted expiring key cookies, bounded inputs/output, and no automatic retry or expensive fallback. App-funded paid AI remains off. API keys must only be entered into the connection panel, never chat. Provider responses are tested with mocks; no real billable provider requests were made for this release.

Theme colour now recolours the existing FitAi artwork in the app header and browser favicon. The install manifest points to cacheable colour-specific PNGs for mobile installations; the app identity stays `/`. Existing installed icon refresh timing depends on the browser/OS. The default static icons remain available offline. Server icon processing accepts only six-digit hex colours and a bounded set of sizes, with a fixed local source file; no user URLs or file paths are read.

Interaction references: [MyFitnessPal Today](https://support.myfitnesspal.com/hc/en-us/articles/39985611667341-Your-Today-tab) for meal-first logging, recent foods and meal reuse; [Hevy workout tracking](https://www.hevyapp.com/features/track-workouts/) for routine-free sessions, exercise selection and previous set values. FitAi keeps its own UI, themes, catalogue and Basic helper.
